# 사방치기 개선 가이드라인

작성 기준: 2026-11-13. 현재 코드·저장된 씬·규칙 문서를 읽어 작성했다. Unity 실행과 HMD 체험은 수행하지 않았다. 이 문서의 개선안은 개발 방향이며, 구현 완료나 규칙 변경을 뜻하지 않는다.


## 원격 병합 후 추가 확인

원격 `d98dba0`의 변경을 반영했다. 아래 조사 표는 병합 전 시점의 기록이며, 최신 코드에는 `CompleteRound()`, `Complete Round On Throw Success`, 다음 목표 지연 시작과 착지 감속·판정 위치 보정이 추가되었다. 프로토타입 8번 최소 종료 신호는 원격에서 구현 완료로 기록되었지만 실제 이동·회전·복귀·망 줍기를 완성한 것은 아니다. 원격의 실행 결과와 미확인 항목은 `Assets/Script/CHECKLIST.md`에서 확인하고 개발 전에 현재 씬을 다시 조사한다. 이번 병합에서는 Unity 실행 검증을 하지 않았다.

## 1. 목표와 적용 범위

**플레이어가 다음 행동을 이해하고, 실패해도 같은 단계에서 다시 시도하며, 1~8번 라운드와 땅따먹기를 끝낼 수 있는 VR 체험을 만든다.**

- 기본 범위는 1인용·8칸·컨트롤러 입력이다. 실제 점프·숙이기·빠른 신체 회전을 요구하지 않는다.
- 세부 규칙은 `Assets/Script/사방치기규칙_구체화.txt`를 따른다. 이 문서만으로 기존 규칙을 바꾸지 않는다.
- 작업 규칙은 루트 `AGENTS.md`, `CLAUDE.md`, `Assets/Script/AGENTS.md`를 따른다.
- 현재 진행 상태와 실행 근거는 `Assets/Script/CHECKLIST.md` 한 곳에 기록한다. 이 문서에 별도의 완료 체크를 만들지 않는다.
- GPT는 우선순위·개발 지시·이미지 제작·결과 검토, Claude는 구현·기술 검증, 사용자는 기획 결정·씬 및 Inspector 연결·HMD 체험 확인을 맡는다.

## 3. 개선 순서와 단계별 통과 기준

### 0단계. 기준 장면과 규칙 대응 확정

먼저 실행 기준을 정하고 문서·화면·판정이 같은 놀이판을 가리키는지 확인한다.

1. `SaBang.unity`, XR Origin, 입력 Action, `Map`, `SabangStone`, 매니저, HUD의 실제 연결을 확인한다.
2. 놀이판 이미지의 1~8번 숫자, Map 구역, 목표 번호, LandingPoint, 외발·양발 속성을 한 표로 대응시킨다.
3. 코드상 구역 형상과 규칙상 이동 순서가 다르면 차이를 기록한다. 현재 그림에 맞춰 규칙을 바꿀지, 규칙에 맞춰 판을 바꿀지는 사용자 결정으로 남긴다. 임의로 번호나 Collider를 옮기지 않는다.
4. 시작 → 선택 → 파워 → 투척 → 실패 재시도 또는 성공 상태 전환을 Play Mode에서 재현한다.
5. 자유 이동·회전·텔레포트 잠금 대상과 계속 활성화할 추적·게임 입력·중단 UI를 구분해 연결한다.

통과 기준: 칸 대응이 확정되고, 현재 투척 루프의 재현 결과와 참조 누락이 기록되며, 시작·중단 시 이동 잠금·복원이 확인된다. 규칙 대응이 미확정이면 독립적인 투척 오류는 고칠 수 있지만 이동 경로는 확정 구현하지 않는다.

### 1단계. 선택·투척·실패 복구 안정화

- 현재 목표 칸과 조준 가능한 위치가 일치하도록 한다. 실제 선택 위치와 표시 Ray·marker의 차이를 확인한다.
- Trigger를 누른 채 다음 단계에 진입해도 위치 선택과 파워 확정이 연속 실행되지 않도록 기존 입력 해제 조건을 유지한다.
- 파워 부족·초과, 다른 칸, 경계선 접촉, 판 밖, 안정화 timeout을 구분해 확인한다.
- 성공·실패 통지는 시도당 한 번만 발생하고, 실패 후 목표 번호를 유지한 채 다시 선택할 수 있어야 한다.
- 실패 안내는 원인을 알 수 있는 짧은 문구로 개선한다. 예: “힘이 약해요. 조금 더 강하게 던져 보세요.”, “선에 닿았어요. 칸 안쪽을 골라 보세요.” 원인 전달 방식은 Claude가 기존 API에 맞게 정한다.
- 중단·컴포넌트 비활성화 시 망·게이지·marker·입력 제한이 남지 않도록 확인한다.

통과 기준: 성공, 파워 부족·초과, 다른 칸, 경계선, 판 밖, timeout의 결과와 재시도를 각각 확인한다. 투척 궤적의 외형 개선과 판정 규칙 변경을 한 작업에 섞지 않는다.

### 2단계. 목표 1번의 한 라운드 완주

투척 성공 뒤 전진 → 회전 → 복귀 → 망 줍기 → 출구 → 라운드 완료를 연결한다. 처음에는 목표 1번을 끝까지 검증하고, 이후 2~8번의 예외를 확장한다.

- 경로는 화면상의 숫자 증가만으로 생성하지 않고 확정한 논리 구역·LandingPoint·입력 유형으로 정의한다.
- 먼저 경로와 QTE 판정을 확인하고 XR 이동을 연결한다. 일반 이동을 잠가도 QTE 이동과 추적은 유지한다.
- 성공하면 다음 지점으로 한 번 이동하고, 실패하면 현재 QTE만 다시 시작한다.
- 회전은 XR Origin 기준으로 처리하되 실제 머리 위치가 틀어지지 않는지 확인한다. 이동·회전 연출 방식은 HMD 체험 후 결정한다.
- 복귀에서 줍기 지점에 도달하면 Grip 안내를 표시한다. 획득 전에는 복귀를 진행하지 않는다.
- 출구 도달과 라운드 완료 신호는 한 번만 처리한다. 중단 뒤 들어온 이전 라운드 이벤트는 진행을 바꾸지 않아야 한다.

통과 기준: 목표 1번을 한 라운드 완주하고, 전진·회전·복귀·줍기 대기 각 단계에서 실패·중단·재시작이 가능하다. 임시 완료 버튼이나 테스트 이벤트가 최종 플레이를 우회하지 않도록 분리한다.

### 3단계. 8개 목표와 땅따먹기·클리어

- 목표 1·2·3·6은 해당 외발 칸을 건너뛴다.
- 목표 4는 5번에서 오른손, 목표 5는 4번에서 왼손 입력을 요구한다.
- 목표 7은 8번에서 오른손, 목표 8은 7번에서 왼손 입력을 요구한다.
- 목표별 전진·회전·복귀·줍기 위치·출구 경로를 표로 만들고 각각 검증한다.
- 8번 라운드 다음에는 목표 9번 투척을 시작하지 않고 땅따먹기로 전환한다.
- 땅따먹기는 경계선에 닿지 않은 1~8번 착지로 소유 칸을 확정하고 첫 소유 칸 획득 시 클리어한다.
- 전체 실패 횟수와 플레이 시간의 소유 주체를 하나로 정한다. 투척의 기존 `FailureCount`와 진행 매니저의 합산이 중복되지 않도록 한다.
- 다시 하기에서 목표·망·경로·소유 칸·시간·실패 횟수·입력 제한·UI를 함께 초기화한다.

통과 기준: 목표별 예외를 확인한 뒤 1~8라운드 → 땅따먹기 → 결과 → 다시 하기를 한 번의 전체 플레이로 확인한다.

### 4단계. 이해하기 쉬운 안내와 체험 품질

안내·실패 사유는 앞 단계에서도 필요한 만큼 개선한다. 전체 흐름이 연결된 뒤 시각·음향·난이도를 집중 조정한다.

- 각 단계에 “지금 할 일” 하나와 입력 아이콘을 표시한다. 선택·투척·이동·회전·줍기 안내가 동시에 남지 않게 한다.
- 목표 칸, 선택 가능 지점, 현재 착지 위치와 다음 이동 지점을 구분한다. 색상 외에 숫자·모양·문구를 함께 사용한다.
- QTE는 어느 손을 언제 눌러야 하는지 표시한다. 실패 시 현재 단계 재시도임을 알려 준다.
- 긴 설명 대신 처음 필요한 시점에 짧은 안내를 제공하고, 안내를 읽는 동안 판정이 시작되지 않도록 한다.
- 성공·실패·착지·줍기의 소리와 햅틱은 짧게 구분한다. 켜짐 여부와 강도는 기존 설정 방식에 맞춰 조절한다.
- 게이지 속도, 허용 범위, QTE 간격, 이동·회전 연출을 한 번에 바꾸지 않는다. 조건과 결과를 기록하며 한 종류씩 조정한다.
- 성능 개선은 HMD·플랫폼·장면·측정 구간을 고정해 측정한 뒤 진행한다. 목표 FPS는 실제 대상 기기와 설정을 확인해 정한다.

통과 기준: 사용자가 다음 행동과 실패 원인을 설명할 수 있고, HMD에서 조준·문구·입력·이동·회전의 불편 사항을 기록하고 필요한 수정을 검증한다.

## 4. 상태와 책임의 경계

기본 흐름은 다음과 같다. 실패는 각 단계 재시도로 돌아가고, 중단은 어떤 진행 단계에서도 준비 상태로 복구한다.

```text
Ready → SelectingPosition → SelectingPower → Throwing
  → MovingForward → Turning → Returning
  → PickingUpStone → Returning → RoundComplete
  → 다음 목표의 SelectingPosition
8번 라운드 완료 → ClaimingLand → Cleared → 다시 하기
```

| 구성 | 맡을 책임 | 확장 시 지킬 경계 |
|---|---|---|
| `UIDoor` | 시작 확인과 진입 위치 이동. | 라운드·QTE 규칙을 넣지 않는다. |
| `Map` | 구역과 경계 안쪽 위치 조회. | 게임 상태·QTE·라운드 진행을 넣지 않는다. |
| `SabangStone` | 선택·파워·비행·투척 결과·망 상태. | 전진·회전·복귀 전체를 관리하지 않는다. |
| `SabangGameManager` | 현재 목표·전체 단계·라운드 전환·중단과 입력 제한. | 동일한 단계를 여러 bool이나 외부 직접 수정으로 중복 관리하지 않는다. |
| 이동·QTE 진행 코드 | 정해진 경로의 입력 판정·이동·완료 통지. | 새 파일 수를 미리 고정하지 않고 기존 구현에 필요한 최소 책임만 분리한다. |
| `UIManager` | 게이지·문구·현재 행동 표시. | 화면 표시가 게임 성공 여부를 결정하지 않게 한다. |

상태 진입 시 필요한 UI와 입력만 활성화하고 상태 이탈 시 타이머·대기 입력·이벤트를 정리한다. 오래된 콜백과 중복 결과로 다음 목표가 두 번 증가하지 않도록 확인한다.

## 5. 구현 전에 정리할 판정 세부사항

| 항목 | 현재 기준 | 다음 개발에서 정할 내용 |
|---|---|---|
| QTE 성공 구간 | 기준점 ±0.25초. | 타임아웃 시점과 경계 포함 여부를 정의하고 양 끝·직전·직후를 검증한다. |
| 양손 QTE | 성공 구간 안에서 입력 차이 0.2초 이내. | 첫 입력 후 둘째 입력을 기다리는 상태와 시간 초과를 명시한다. |
| 외발 동시 입력 | 양손 동시는 실패. | “동시”를 인정하는 시간 범위가 명시되지 않았다. 0.2초 사용은 제안이며 사용자 확인 후 규칙에 기록한다. 첫 손 입력 즉시 성공 확정 시 뒤따르는 손을 놓치는 문제를 검토한다. |
| 돌아올 때 손 대응 | 좌우 칸과 손 대응 규칙이 있다. | 180도 회전 후 좌우가 판 기준인지 시야 기준인지 확정한다. 안내와 판정이 같은 기준을 사용해야 한다. |
| 망 줍기 | 돌 바로 앞 구역에서 Grip. | 목표 1번의 출구 근처와 목표 7·8번의 회전 지점에서 언제 줍는지 경로별로 명시한다. |
| 시간 기록 | 완료 시간 표시. | 시작·종료 시점, 일시정지·재시도 시간 포함 여부를 정한다. |
| 전체 실패 | 모든 실패 횟수 표시. | 투척·이동·회전·땅따먹기 실패를 각 시도당 한 번 합산하도록 기준을 명시한다. |
| 중단 UI | 게임 중 일반 UI 입력 제한 코드가 있다. | 로비 UI 제한과 게임의 중단·결과·다시 하기 입력을 구분한다. 복구에 필요한 UI까지 잠그지 않는다. |

미확정 사항은 해당 기능 구현 전에 묶어서 사용자에게 확인한다. 독립적으로 가능한 연결 점검·투척 검증을 기다리게 하지 않는다.

## 6. 이미지 작업의 시점과 범위

- 기본 루프 확인 단계에서는 기존 놀이판·텍스트·단순 marker를 사용한다.
- 놀이판 번호·구역 대응이 확정되기 전에 새 판 이미지를 최종 제작하지 않는다. 이미지 변경은 `Map`의 판정 영역과 함께 확인한다.
- GPT의 이미지 후보는 손 입력 안내, 망 줍기 안내, 전통 문양, 결과 화면 장식이다. 한 번에 하나의 용도를 정하고 확정된 그림체를 따른다.
- 각 요청에는 사용 위치, 원본 크기·종횡비·알파, 개수, 시트 또는 개별 파일 여부, 기존 UI 참조를 포함한다. 규격은 실제 Canvas·에셋 용도 확인 후 정한다.
- QTE 표시자·게이지 진행·성공 영역·선택 강조와 같이 변하는 정보는 Unity UI·머티리얼·코드로 표현한다.
- Claude가 가공·에셋 반영·규격 확인을 맡고, 사용자가 씬·Inspector 연결 후 HMD 가독성을 확인한다.

## 7. Claude에 맡길 작업 단위

한 작업은 목표 하나, 수정 경로, 필요한 연결, 검증 시나리오, 결과 메모를 갖춘다. 실제 작업 번호는 우편함의 기존 번호를 확인한 뒤 부여한다.

| 순서 | 작업 | 산출물과 완료 조건 |
|---|---|---|
| A | 현재 구현·씬 연결과 칸 대응 조사. | 연결 표, 규칙 차이, Play Mode 재현 결과, 사용자 결정 목록. |
| B | 일반 이동·UI 입력 제한과 중단 복구 확인. | 필요한 Inspector 목록, 원래 활성 상태 복원, 추적·게임 입력 유지 확인. |
| C | 선택·투척 회귀 확인과 발견된 문제 수정. | 성공·실패 사유·이벤트 한 번·재시도 결과. |
| D | 한 구간 QTE 판정과 이동. | 외발·양발·시간 경계·누른 채 진입·실패 재시도 확인. |
| E | 목표 1번 전진·회전·복귀·줍기·완료. | 한 라운드 완주와 각 단계 중단 복구. |
| F | 목표 2~8번 경로와 예외. | 목표별 경로 표와 실행 결과. |
| G | 땅따먹기·통계·클리어·다시 하기. | 전체 플레이와 초기화 결과. |
| H | 안내·이미지・소리·햅틱·난이도 조정. | 변경 전후 조건과 HMD 체험 기록. |

## 8. 단계별 보고 양식

결과는 기존 체크리스트의 작업 기록 또는 해당 우편함 결과 메모에 남긴다.

- 실제 동작의 변경 전 → 변경 후.
